# 协作者接入指南

> 给每位新成员：拿到仓库写权限后，按本页一次配好，之后正常 `git pull / push` 即可。

---

## 0. 前置条件

- 已被邀请为仓库协作者（GitHub 会发邀请到你的账号邮箱或通知，点接受）
- 已加入本项目（WorkBuddy），能看到**项目消息**里发布的共享令牌

## 1. 配置 git 身份（每人一次）

```bash
git config --global user.name  "你的名字"        # 例如：张三
git config --global user.email "你的GitHub邮箱"   # 用 GitHub 账号邮箱
git config --global core.autocrlf false           # 换行交给 .gitattributes 统一
git config --global pull.rebase true
```

身份决定提交署名，**务必配置**，否则提交历史里会出现机器默认名。

## 2. 获取仓库写凭证

项目当前使用**共享令牌（Personal Access Token）**方式推送。令牌发布在
**本项目（WorkBuddy）的项目消息**中，标题：`GitHub 仓库推送凭证（共享令牌）`。

> ⚠️ **令牌纪律，逐条遵守**：
> 1. 只用于本仓库，不外发、不上任何网站
> 2. **严禁提交进代码仓库** —— 仓库是公开的，令牌一旦入库会被 GitHub 自动吊销
> 3. 不要把令牌写进 remote URL（会明文存进 `.git/config`），用下面的凭据管理器方式
> 4. 屏幕共享、截图、贴聊天工具时注意遮挡

## 3. 克隆与首次推送

推荐用 **Git 凭据管理器**（Windows 装 Git 时自带；macOS/Linux 执行
`git config --global credential.helper manager`）：

```bash
git clone https://github.com/xiaosp1/Unmanned-Warehouse-System.git
cd Unmanned-Warehouse-System

# 拿一个测试分支验证权限
git switch -c test/我的首次推送
echo ok > test.txt && git add test.txt && git commit -m "test: 验证推送权限"
git push -u origin test/我的首次推送
```

首次 push 弹出登录框时：

| 字段 | 填什么 |
| --- | --- |
| 用户名 | 你的 GitHub 用户名 |
| 密码 | **粘贴共享令牌**（GitHub 已不接受账号密码） |

推送成功后删掉测试分支，走正式流程（[CONTRIBUTING.md](../CONTRIBUTING.md)）。

<details>
<summary>没有凭据管理器时的替代方案（令牌明文落盘，仅限个人开发机）</summary>

```bash
git config --global credential.helper store
git push   # 首次输入用户名 + 令牌，之后不再询问；令牌保存在 ~/.git-credentials
```
</details>

## 4. 关于共享令牌，你需要知道的

| 问题 | 说明 |
| --- | --- |
| 提交署名 | 显示你自己的 `user.name / user.email`，令牌只做身份验证，不会冒名 |
| 令牌归属 | 属于仓库所有者的个人令牌，**权限较大**，务必遵守上面的纪律 |
| `main` 分支 | 受保护：不能直推，一律推 `feat/*`、`fix/*` 短分支后提 PR |
| 谁来评审 | `CODEOWNERS` 决定各路径的必评审人；引导期全部由 @xiaosp1 评审 |
| 何时换 | 团队稳定后改为**每人一个细粒度令牌**（GitHub → Settings → Developer settings → Fine-grained tokens，只授权本仓库、Contents: Read and write），共享令牌随即吊销 |

## 5. 常见问题

**push 报 `Authentication failed`**
→ 令牌输错或已被吊销。回项目消息重新复制，注意别带上多余空格。

**push 报 `non-fast-forward` / `fetch first`**
→ 远端有你没有的提交：`git pull --rebase` 后再推。

**push 到 `main` 被拒**
→ 这是设计如此，`main` 必须走 PR。见 [01-仓库与分支规范.md](./01-仓库与分支规范.md)。

**想改别人的模块**
→ 先在项目消息里找 CODEOWNERS 对应的责任人对齐，再动手，避免返工。
